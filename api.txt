Pour votre application de prédiction du risque de diabète avec Spring Boot, JWT, historique et SHAP, voici une architecture d’API complète et professionnelle.

Je vais les organiser par module comme dans une vraie application SaaS médicale.

---

# Architecture REST API recommandée

```text id="9om8x0"
/api
├── /auth
├── /users
├── /predictions
├── /dashboard
└── /health
```

---

# 1. AUTH APIs

Module authentification.

---

## POST `/api/auth/register`

Créer un compte.

### Request

```json id="vkxlyx"
{
  "nom": "Elkasraoui",
  "prenom": "Soufiane",
  "email": "soufiane@gmail.com",
  "password": "Password123",
  "dateNaissance": "2004-08-15"
}
```

### Response

```json id="hjwb3g"
{
  "message": "Utilisateur créé avec succès"
}
```

---

## POST `/api/auth/login`

Connexion utilisateur.

### Request

```json id="4f7r8m"
{
  "email": "soufiane@gmail.com",
  "password": "Password123"
}
```

### Response

```json id="0nq6om"
{
  "token": "jwt_token_here",
  "user": {
    "id": 1,
    "nom": "Elkasraoui",
    "prenom": "Soufiane",
    "email": "soufiane@gmail.com"
  }
}
```

---

## GET `/api/auth/me`

# 3. PREDICTION APIs

Le cœur du projet.

---

## POST `/api/predictions`

Créer une nouvelle prédiction.

Cette API :

* valide les données,
* appelle le modèle ML,
* récupère :

  * risk_score
  * risk_level
  * shap_values
* sauvegarde en DB.

---

## Request

```json id="5ytw7f"
{
  "highBp": true,
  "highChol": false,
  "cholCheck": true,
  "bmi": 31.2,
  "smoker": false,
  "stroke": false,
  "heartDiseaseOrAttack": false,
  "physActivity": true,
  "fruits": true,
  "veggies": true,
  "hvyAlcoholConsump": false,
  "genHlth": 3,
  "mentHlth": 4,
  "physHlth": 7,
  "diffWalk": false,
  "sex": "MALE",
  "age": 8
}
```

---

## Response

```json id="7u98ul"
{
  "predictionId": 12,
  "riskScore": 0.73,
  "riskLevel": "HIGH",
  "shapValues": {
    "bmi": 0.31,
    "highBp": 0.22,
    "genHlth": 0.18,
    "physActivity": -0.11
  },
  "createdAt": "2026-05-09T19:20:00"
}
```

---

## GET `/api/predictions`

Historique utilisateur.

### Query Params optionnels

```text id="z9vhhg"
?page=0
&size=10
&sort=createdAt,desc
```

---

## GET `/api/predictions/{id}`

Détails d’une prédiction.

---

## DELETE `/api/predictions/{id}`

Supprimer une prédiction.

## Profile

# APIs probablement inutiles pour PFA

Vous pouvez éviter :

* refresh token
* email verification
* forgot password
* OAuth Google
* admin panel complet
